# internal/tree_arena

[索引](../../README.md) / [実装](../../../../library/data_structure/internal/tree_arena.hpp)

## 機能・前提条件

可変木のノードプール・再利用リスト・平衡化Backendをまとめる内部の所有領域です。ノードごとの参照カウントやdeleteは行いません。列・集合ハンドルはshared_ptrでarena全体を共有所有します。可変ノード自体は複数の木で共有しません。管理型のmove代入でも既存ハンドルのarenaは保持されます。これは管理型の破棄・置換で無効になる借用の永続Rootとは異なります。

## インターフェース

`TreeArena<Ops,Backend>` はNodePool、free_nodes、engineを保持します。create(args...)は新規または再利用ノードを構築し、engine.prepareを実行します。release(node)は切り離し済みの単一ノードの参照を無効にし、再利用リストへ戻します。公開済み永続ノードには使用しません。

不透明なNodeRefの状態は参照の取得時だけ確保します。arenaはノードをキーとする表に弱参照を持ち、
NodeRefもarenaを所有しません。異arenaへ値を移送するときは同じ参照状態を移送先のノードへ付け替えます。
順位取得は親をたどって所属する根を確認し、根からpushする過程で現在の左右関係に沿って順位を加算します。
成功時にはBackendで対象にアクセスするため、splayの償却計算量が維持されます。

同一arenaの作業領域と乱数状態を共有します。同一arenaへの並行操作・演算callbackからの再入は想定しません。

## 計算量

create/releaseはハッシュ表の操作を含め期待償却 O(1)。A確保ノードに O(A) 空間、Backendの作業領域を加えます。参照管理の表は参照を取得したノード数以下のエントリを持ちます。領域全体の破棄は O(A)。

## 性能比較

[既存ベンチマーク](../../../../tools/benchmarks/tree_collections.cpp)をg++の
`-std=c++20 -O2 -DNDEBUG`で各5回実行しました。列は4要素ずつ32,768列を構築し、32,767回concat。
集合は偶数・奇数キー各100,000個を挿入し、meldしてから偶数キー100,000個を削除しました。
いずれも要素参照を取得しない場合の中央値と最大RSSです。

| 対象 | 時間 ms（前 → 後） | 最大RSS KiB（前 → 後） | ノード bytes（前 → 後） |
| --- | ---: | ---: | ---: |
| splay列 | 4.95 → 4.91 | 11,304 → 11,304 | 56 → 56 |
| treap列 | 7.46 → 7.03 | 12,464 → 12,432 | 64 → 64 |
| splay集合 | 42.38 → 43.38 | 17,712 → 17,808 | 64 → 64 |
| treap集合 | 79.21 → 83.90 | 17,556 → 17,556 | 64 → 64 |

チェックサムは全条件で一致しました。集合の処理時間には増加が見られましたが、
参照を取得するまで管理用エントリを確保せず、通常ノードの大きさを維持できる構成を採用しました。
